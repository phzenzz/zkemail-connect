## P1 · 封面
- 项目名 + 一句话定位：**"给任何邮箱地址发 USDC，对方回一封邮件就能收到。"**
- 视觉：手机 mockup —— 通知邮件 → 领取页面 → 到账，三步并排

## P2 · 问题（Problem）
- 链上转账/空投的最大漏斗：接收方没有钱包、不懂助记词
- 发送方明知道对方邮箱，却没办法把钱给到对方
- 现状取舍：
  - 中心化托管 → 信任黑洞，钱在别人手里
  - 现有的"邮箱钱包"产品 → 要用户按格式写邮件指令，没人会用
  - 链接/表单领取 → 平台可以偷偷换掉收款地址，发送方无法信任
- 一句话总结：**"收钱"这个最简单的需求，是 Web3 获客链路上最脆的一环**

## P3 · 产品（Solution）
- 3 步流程图（发送方 / 接收方视角各一屏）：
  1. 发送方：输入邮箱 + 金额，一键发币
  2. 接收方：收邮件 → 打开领取页 → 粘贴收款地址 → 点"发送"（系统自动生成回复邮件）
  3. 资金到账，全程接收方不需要钱包、不需要注册、不需要助记词
- 关键卖点（业务语言）：**收款地址由邮件本身密码学锁定，平台碰不到钱、改不了地址，全程可公开审计**

## P4 · 为什么是现在（Why Now）
- 稳定币支付/转账进入爆发期，"给没有钱包的人付款"成为高频真实需求
- 密码学基础设施刚成熟：DKIM 邮箱签名 + 零知识证明第一次让"邮箱所有权"可以被链上验证，成本低到可以忽略
- 头部交易所（OKX）已用同类技术做钱包恢复并过审计 —— 技术路线被生产验证
- 窗口期：这个品类还没有赢家

## P5 · 市场空间（TAM / SAM / SOM）
- TAM：全球稳定币转账 + 加密支付/营销发放市场
- SAM：Solana 生态内"向非托管用户发放资产"的场景（支付、空投、打赏、薪酬）
- SOM：从加密社群"给新人发第一笔 USDC"切入
- （数字待补，PPT 生成前填入最新数据）

## P6 · 商业模式（Business Model）
- 领取服务费：每笔领取收取小额手续费（代付 gas + 服务费），随规模线性增长
- 企业 API：批量发放/营销空投按量计费（SaaS）
- 免费侧刻意做大：发送方免费发，让"邮箱收款"成为网络入口
- 定价对标：远低于中心化托管方案的信任溢价

## P7 · 竞争格局（Competition）
- 三列表：本方案 vs 中心化托管 vs 现有邮箱钱包
  - 接收方门槛：回一封邮件 vs 注册并信任平台 vs 按格式写邮件
  - 资金安全：平台零接触 vs 平台持有 vs 视实现
  - 可组合性：开放协议 vs 封闭账户 vs EVM 局限
- 护城河：先发 + DKIM 服务商兼容性矩阵（每个邮箱域名的适配都是积累）+ 协议开源建立标准

## P8 · 产品与增长（Product & Traction）
- 产品现状：核心流程已端到端跑通（真实邮件 → 领取 → 上链到账），不是 PPT 项目
- 用户体验数字：4 次点击 + 1 次粘贴完成领取；主流邮箱服务商全覆盖
- GTM：加密社群新人引导（"邮件里的第一个钱包"）→ 支付/打赏场景 → 企业批量发放
- 增长飞轮：每个接收方 = 一次零成本的 Web3 新用户转化

## P9 · 路线图（Roadmap）
- 已完成：核心产品端到端闭环 ✅

- 12 个月：批量发放、可退款托管、嵌入式钱包（Face ID 创建地址）、多链
