# 手动测试指南

把 `npm run e2e`（`e2e/e2e.ts`，全自动）拆成可以逐条执行的手动命令，方便单步调试。
分三部分：**一次性环境准备** → **启动环境（节点 + prover）** → **逐步发交易**。

> **前置注意**
> - 测试邮件 `circuits/testdata/emails/e2e.eml` **不入库**（含个人信息），先按 `circuits/testdata/emails/README.md` 从真实邮箱导出一份再开始。
> - 邮件 DKIM 新鲜度窗口 **48 小时**，过期后步骤 01 会报错，需重新导出。
> - 所有命令默认在 **repo 根目录**执行（出证明那步除外，需在 `circuits/` 下）。
> - 手动测试的中间产物（密钥对、state、proof）都放在 `.manual-test/`（已 gitignore）。
> - 全程用同一个 relayer 密钥对——证明绑定 relayer 公钥，换了会导致 claim 失败。

---

## 一、一次性环境准备

依赖编译过就可以跳过。改动电路或 relay 地址后需要重跑对应步骤。

```bash
# 1. 安装依赖（需要 GitHub SSH，见 README）
npm install && (cd circuits && npm install)

# 2. 编译电路（约 10 分钟）
bash circuits/scripts/compile.sh

# 3. trusted setup（build/pot22_final.ptau 已存在则跳过 4.8GB 下载）
bash circuits/scripts/setup.sh

# 4. 生成链上 verifying key 并拷入程序
(cd circuits && node scripts/gen-vk-rust.mjs)
cp circuits/build/verifying_key.rs onchain/programs/email-wallet/src/verifying_key.rs

# 5. 构建链上程序（产出 .so 和 IDL）
export PATH="$HOME/.avm/bin:$PATH"
(cd onchain && anchor build)
```

> 改 relay 地址（`circuits/relay.config.json`）要用 `bash circuits/scripts/rebuild.sh` 代替上面的 2–4 步。
>
> **注意：只要动了电路或 zkey（`compile.sh` / `setup.sh` / `rebuild.sh`)，链上 vk 就必须同步**——重跑第 4 步（`gen-vk-rust.mjs` + `cp`)再 `anchor build` 并重启 validator，否则 prover 用新 zkey 出的证明在链上旧 vk 下会报 `ProofVerificationFailed`。

## 二、启动环境（每次测试）

### 终端 1：启动本地节点（已部署程序）

```bash
export PATH="$HOME/.avm/bin:$PATH"
solana-test-validator --reset --log \
  --bpf-program "$(solana address -k onchain/target/deploy/email_wallet-keypair.json)" \
  onchain/target/deploy/email_wallet.so
```

`--log` 会把 validator 日志（含每笔交易的 program log）打到终端，方便排查失败交易；
不想占前台终端的话，也可以在另一个终端用 `solana logs --url http://127.0.0.1:8899` 订阅日志。

另开一个终端确认节点起来了：

```bash
solana slot --url http://127.0.0.1:8899
```

### 终端 2：启动 prover 容器

```bash
docker compose up -d --build prover
```

等健康检查通过（首次构建镜像较慢）：

```bash
until curl -sf http://localhost:8080/health >/dev/null; do sleep 1; done && echo prover ready
```

## 三、逐步发交易

每一步一条命令，按顺序执行；任何一步失败都可以修完后单独重跑该步。

> **v1.6 顺序说明**：04（注册 relayer）必须先于 02（建托管）执行——createEscrow 要求链上已注册
> relayer 且 cipher 用其 x25519 公钥加密。04 是幂等脚本：第一次跑（01 之后、02 之前）完成
> protocol 初始化 + relayer 注册；此时还没有 proof.json，DKIM upsert 会自动跳过，
> 03 步出完证明后再跑一次 04 补齐即可。

### 步骤 0：生成密钥对并空投

```bash
npx tsx e2e/manual/00-setup.ts
```

生成 `.manual-test/sender.json` / `relayer.json`（已存在则复用），各空投 5 SOL。

### 步骤 01：解析邮件

```bash
npx tsx e2e/manual/01-parse-email.ts
```

真实 DNS 验 DKIM、检查 48h 新鲜度、校验 To/Subject，把 commitment / selector / dest 写入 `.manual-test/state.json`。**这一步失败说明邮件本身有问题（过期/格式不对），先解决再继续。**

### 步骤 04（第一轮）：初始化 protocol + 注册 relayer（运营侧）

```bash
npx tsx e2e/manual/04-registry.ts
```

初始化 protocol config（treasury + 手续费 0.001 SOL）并注册 relayer（`RELAYER_EMAIL = relay@zkemail.io`）。
脚本是幂等的：protocol 已初始化 / relayer 已注册时会自动跳过。
**把打印的 `relayer x25519 secret (hex)` 存好——启动 relayer 索引器时要用**（同时也会写入 `state.json` 的 `relayerX25519Secret` 字段，02 步据此加密）。
此时 proof.json 尚不存在，DKIM upsert 会跳过（见 03 之后的第二轮 04）。

### 步骤 02：建托管（sender 打币，加密邮箱 + 协议手续费）

```bash
npx tsx e2e/manual/02-create-escrow.ts
```

创建 SPL mint、sender ATA、铸币；读取链上 relayerEntry 与 protocolConfig，
用 `state.json` 里的 relayer x25519 公钥把收件邮箱加密进 cipher（占位为 `recipient@example.com`，
手动测试时改成真实收件邮箱），然后 `createEscrow`（commitment + amount + cipher + relayer hash）
把代币锁进 vault，并给 treasury 支付协议手续费。

### 步骤 2.5（可选）：手动验证 relayer 索引器

另开一个终端，用 04 步打印的 secret hex 启动索引器：

```bash
RELAYER_EMAIL=relay@zkemail.io RELAYER_X25519_SECRET_HEX=<04 步打印的 hex> RPC_URL=http://127.0.0.1:8899 npx tsx relayer/indexer.ts
```

02 步建的托管上链后，索引器应打印 `[notify] to=<收件邮箱> escrow=... claim=...`——
即它用 x25519 私钥解密了 cipher、校验 Poseidon commitment 一致后"通知"了收件人。

### 步骤 03：出证明（走 prover 容器）

```bash
cd circuits && PROVER_URL=http://localhost:8080 \
  npx tsx scripts/prove-for.ts \
    testdata/emails/e2e.eml \
    "$(solana address -k ../.manual-test/relayer.json)" \
    ../.manual-test/proof.json && cd ..
```

产物 `.manual-test/proof.json` 包含 proofA/B/C、publicInputs 和邮件元数据。
不设 `PROVER_URL` 则走本地 snarkjs（慢但不需要 Docker）。

### 步骤 04（第二轮）：注册 DKIM 公钥（运营侧）

```bash
npx tsx e2e/manual/04-registry.ts
```

再跑一次 04：protocol / relayer 部分自动跳过，这次 proof.json 已存在，
初始化 registry（首个调用者成为 authority，重复执行会自动跳过）并 upsert 该服务商的 DKIM 公钥哈希。

### 步骤 05：claim（relayer 代付发交易）

```bash
npx tsx e2e/manual/05-claim.ts
```

单笔交易完成：链上 Groth16 验证明 → 解码 Subject 里的 dest → 转账 → 关闭 escrow/vault。

### 步骤 06：验证终态

```bash
npx tsx e2e/manual/06-verify.ts
```

断言：dest ATA 收到足额代币、escrow 和 vault 账户已关闭。

## 四、清理

```bash
# 终端 1 按 Ctrl+C 停掉 validator（或：pkill solana-test-validator）
docker compose down
rm -rf .manual-test onchain/test-ledger
```

想重新开始一轮：清掉 `.manual-test/`、重启 validator（`--reset` 会重置账本），再从步骤 0 跑起。

## 常见问题

| 现象 | 原因 |
|------|------|
| 步骤 01 报 `.eml is XXh old` | 邮件超过 48h 新鲜度窗口，重新导出 e2e.eml |
| 步骤 01 报 `To is not ...` | 邮件 To 头不等于 `circuits/relay.config.json` 里的 relay 地址（大小写敏感） |
| 步骤 02 报 `state 缺 relayerX25519Secret` / 链上无 relayerEntry | 先跑步骤 04（注册 relayer）再跑 02 |
| 步骤 02 报 `unauthorized registry authority` / treasury 不匹配 | treasury 必须等于 protocol config 里登记的那个（脚本自动从链上读取，一般不用管） |
| 步骤 2.5 indexer 无 `[notify]` 输出 | `RELAYER_X25519_SECRET_HEX` 与 04 步注册用的不是同一把 key（02 会断言 state 与链上 entry 一致）；或 escrow 的 relayer hash 与本机 RELAYER_EMAIL 不符 |
| 步骤 03 prover 连接失败 | prover 容器没起或没过健康检查，回第二节终端 2 |
| 步骤 05 报 proof 校验失败 | relayer 密钥对和出证明时不是同一个，或 VK 与电路不匹配（重跑准备第 4 步） |
| `anchor: command not found` | `export PATH="$HOME/.avm/bin:$PATH"` |
